# Planning

[Chapter overview](README.md) | [Course home](../README.md)

## In plain English

Planning determines actions and dependencies needed to achieve a goal. A useful plan names the input, intended output, checks and stopping condition. Plans can be revised when new information changes the available options. Some tasks are simple enough to act directly; others require explicit decomposition. Keep a plan proportional to the task, and distinguish a planned action from one that has actually been performed.

## Try it: original exercise

1. Break a repository tutorial task into source extraction, writing, validation and export.
2. Identify dependencies: the approved topic map must precede lesson writing.
3. Place approval gates before major scope or publication decisions.
4. Update the plan when a source redirect or missing input changes the workflow.

## Check your understanding

Is a plan that lists "create PDF" evidence that the PDF exists?

**Answer checkpoint:** No. Completion requires the generated file and evidence that it was checked.

## Common mistake

A detailed plan can still be wrong if it depends on tools or permissions the agent lacks.
