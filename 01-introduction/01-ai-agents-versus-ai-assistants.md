# AI agents versus AI assistants

[Chapter overview](README.md) | [Course home](../README.md)

## In plain English

An assistant usually helps through interaction; an agent can carry an objective through several actions. These are overlapping behaviors, not permanent product categories. A system that drafts a troubleshooting reply is assisting. If it reads a ticket, retrieves the correct runbook, checks relevant records and produces a documented resolution proposal, it is doing agentic work. Count actions and observable outcomes rather than trusting the product label. Autonomy should match the task and the permissions you actually granted.

## Try it: original exercise

1. Write an advice request: explain how to organize support tickets.
2. Rewrite it as a goal: inspect six tickets and create a categorized summary.
3. Specify the input file, output location, category rules and approval boundaries.
4. Compare the explanation with the resulting artifact and the recorded actions.

## Check your understanding

Is a fluent answer enough to demonstrate that an agent completed a workflow?

**Answer checkpoint:** No. Look for actual inspected inputs, tool actions and a usable result that meets the goal.

## Common mistake

A chatbot interface can expose agent capabilities; an agent-branded product can still be used only for text generation.
